# Portable Custom Profile Libraries
Objective: portable folder libraries containing editable, autonomous section sketches; branch: `feat/portable-custom-libraries` (base `7eb2f38`, verified default `main`).
Delivery: `auto-chain` / `feature-branch-chain`, local reviewable work-unit commits only; no push/PR/merge authorization. Tests: isolated FreeCAD GUI offscreen, public APIs, distinct RED/GREEN logs, per-unit differential controls.

## Specs

S1. User objective: "Bien ahora analicemos y halemos de como manejar los Perfiles PErsonalizado en el Gestor de Bibliotecas". Implementation was subsequently authorized by "ok" after the staged implementation proposal recorded in L6. Checks: library management and profile creation work together without replacing existing standard catalog behavior.

S2. User choice: "EL croquis editable, como se guardaria el croquis (o la copia del croquis original)?" Checks: a stored section is an editable native sketch, not only a static BREP/face; its independent copy can be saved, reopened and edited without the original document. Source documents remain unchanged.

S3. User requirement: "Quiero Guardar las lib personalizadas en una carpeta (que contenga la lib y todos los archivos necesarios) que el usuraio pueda elejir para poder exportar esa lib y usarla en otras PC. por ejmplo podria elejir una carpeta de google drive (sincronizada) y en otra pc importlar lib y elegir la misma carpeta asi puede manejar los mismos perfiles en puestos de trabajo distintos o compartirla con otros compañeros de trabajo." Checks: user-selected self-contained library root, relative section references, register an existing library in place, and relocate/copy a complete library without broken references. Machine-specific registration is separate from portable content. Existing stock/user libraries continue to work and are not moved automatically.

S4. User requirement: "Aceptemos cualquier tipo de croquis valido (autonomos o no) pero lo volveremos autonomo al crear la copia convirtiendo las referencias externas en valores fijos (por ejemplo si una cota hace referencia a VarSet.Ancho= 250 pasamos la cota a 250) entiendes la idea? es posible? pros contras?." Checks: freeze evaluated external dimensions with correct units; materialize external geometry while preserving construction/defining status and remapping constraints; detach source support while preserving local section coordinates. Validate equivalent section geometry and independence before persisting; never silently save a different section. Preserve independently usable internal constraints/formulas where supported. Record unsupported conversion proof honestly rather than claiming a universal converter from bounded examples.

S5. User section decision: "Solo una región conectada" (option description: "Aceptar una sección continua con los huecos que necesite; rechazar regiones de material separadas con un mensaje claro."). Checks: reuse the existing custom-section validator, supporting holes/curves and ignoring construction geometry; invalid/open/crossing/disconnected geometry is rejected without data loss. This does not authorize arbitrary source-plane reorientation in the profile generator.

S6. User concurrency decision: "una persona por vez, si hay concurrencia que lo maneje el sistema de sincorizacion que use el usuario no dependera de nosotros." Checks: ordinary reliable local persistence and local filesystem errors, no sync-provider integration, distributed locks, or remote conflict resolution. Do not promise that any external provider resolves conflicts correctly.

S7. User delivery choice: "Cadena sobre rama de funcionalidad — recomendado" after approval "ok" of the implementation organization. Checks: feature-branch work units with their tests/docs and commit evidence; default branch remains unchanged; publishing and final integration remain separate user decisions.

S8. User approval "ok" of the implementation organization in L6 includes creating/registering a folder library, capturing autonomous sections, manager CRUD, profile creation from library, and complete-library duplication/portability. Checks: library edits do not automatically modify existing project sections; inserted projects carry document-local section sources and can reopen without library availability. Keep per-library material semantics and existing dimensional catalog behavior unchanged. UI labels/help/docs describe new actions and diagnostics.
